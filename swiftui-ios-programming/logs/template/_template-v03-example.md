# 학습 로그 템플릿 v03 작성 안내와 예시

> 이 파일은 `_template-v03.md`의 사용법을 보여주는 가상 예시다. 실제 학습 기록으로 사용하지 않는다.

## 핵심 구조

v03은 **시간과 하루 요약만 고정하고, 세션 내용은 자유롭게 작성하는 템플릿**이다.

1. `기본 정보`에 오늘의 목표와 총 학습 시간을 적는다.
2. 각 세션에 시작·종료·공부 시간을 적는다.
3. 시간 아래에는 필요한 내용만 자유롭게 적는다.
4. 마지막에 오늘의 한 줄, 상태, 다음 시작점을 남긴다.

세션 안에는 학습 범위, 이해한 개념, 코드, 오류와 해결, 질문, 참고 링크 등을 모두 적을 수 있다. 필요 없는 항목을 억지로 채울 필요는 없다. 세션이 하나라면 `세션 2`를 삭제하고, 세 번 이상이라면 세션 블록을 복사한다.

머리말의 `duration_minutes`에는 모든 세션의 합계를 숫자로 적는다. `status`에는 `planned`, `in-progress`, `completed`, `blocked` 중 하나를 사용한다.

## 완성된 작성 예시

아래 예시는 같은 세션 안에서도 문단, 목록, 코드, 질문을 자유롭게 섞어 쓸 수 있음을 보여준다.

````markdown
---
template_version: "03"
date: 2026-08-21
book: swiftui-ios-programming
study_day: 3
elapsed_day: 8
duration_minutes: 55

---

# 2026-08-21

## 기본 정보

- 누적 실학습일: 3일
- 시작 후 경과일: 8일차
- 오늘의 목표: `@State`와 `@Binding`의 차이를 이해하고 작은 예제로 확인한다.
- 총 학습 시간: 55분

## 세션 1

- 시작 시간: `09:00`
- 종료 시간: `09:25`
- 공부 시간: 25분

120-123쪽을 읽고 `@State`를 사용하는 카운터를 만들었다.

`@State`는 뷰가 소유하는 변경 가능한 상태다. 버튼으로 상태를 바꾸면 그 상태를 사용하는 화면이 다시 갱신된다.

```swift
@State private var count = 0
```

처음에는 일반 프로퍼티를 버튼 안에서 변경해서 컴파일 오류가 났다. `@State`로 바꾼 뒤 빌드와 화면 갱신을 확인했다.

다음 세션에서는 카운터 값을 자식 뷰에 전달해 본다.

## 세션 2

- 시작 시간: `20:10`
- 종료 시간: `20:40`
- 공부 시간: 30분

124-127쪽의 `@Binding` 예제를 따라 하고 부모·자식 뷰로 나눠 다시 만들었다.

- 부모는 `@State`로 값을 소유한다.
- 자식은 `@Binding`으로 그 값에 연결된다.
- 부모에서 자식으로 전달할 때 `$count`를 사용한다.

숫자가 0보다 작아지지 않도록 감소 버튼도 바꿔 보았다. 예상대로 0에서 값이 더 내려가지 않았다.

아직 남은 질문: `$`가 만들어 내는 값의 정확한 타입은 무엇인가?

## 하루 마무리

- 오늘의 한 줄: `@State`는 상태를 소유하고 `@Binding`은 그 상태에 연결된다.
- 오늘의 상태: `완료`
- 다음 시작점: 오늘 만든 부모·자식 뷰를 책을 보지 않고 다시 작성한다.
````
