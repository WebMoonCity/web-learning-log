#### 3.2.5 프로미스

* 콜백 함수(callback function): 이벤트가 발생했을 때 특정 작동을 수행하는 함수.

- 동기(synchronous): 요청을 보내고 응답을 받을 때까지 대기했다가, 응답을 받으면 다음 작업을 시작하는 처리 방식을 뜻함.
- 비동기(asynchronous): 응답을 보내고 다른 일을 하다가, 작업이 끝났다는 이벤트가 발생하면 응답을 처리하는 방식.

* 프로미스 문법
    - 성공과 실패를 분리

#### 3.2.6 구조 분해 할당

#### 3.2.7 나머지 연산자, 전개 연산자

- 나머지 연산자와 전개 연산자는 똑같이 생겼기 때문에 헷갈리기 쉬움.

* 나머지 연산자: 말 그대로 구조 분해 할당을 하고 남은 값들을 변수 하나에 할당할 때 사용.
* 전개 연산자: 객체를 전개해 값을 할당할 때 사용하며, 앞서 설명했던 깊은 복사를 하거나 기존의 객체를 확장할 때 사용.

#### 3.2.8 옵셔널 체이닝과 null 병합

* 타입스크립트에서 null을 참조할 경우 에러가 발생.(undefined도 마찬가지)

* 옵셔널 체이닝(optional chaining): 참조하기 전에 물음표(?)를 붙여주면 됨. 참조하는 데이타가 정말 있는 것인지 확신할 수 없기 때문에 데이터가 있다면 데이터를 반환하고, 데이터가 없다면 undefined를 반환함.

* null 병합 연산자(??): 왼쪽에 있는 피연산자가 null 혹은 undefined일 때 기본값을 설정할 수 있음.

- 옵셔널 체이닝과 null 병합 연산자를 같이 활용해서 오류를 줄이고 의도한 값으로 유도할 수 있음.

#### 3.2.9 모듈

* 모듈(module): 코드들을 파일 단위 혹은 디렉터리(폴더) 단위로 분리하여 유지 보수를 함. 이 각각의 파일을 모듈이라고 함.

## 4 타입스크립트 스킬

### 4.1 타입 추론과 타입 주석

#### 4.1.1 타입 추론
* 타입 추론(type inference): 타입스크립트에서는 변수에 초깃값을 할당할 때 그 값의 타입을 기준으로 자동으로 변수의 타입이 결정됨.

#### 4.1.2 타입 주석

* 타입 주석(type annotation): 콜론(colon) 옆에 변수의 타입을 지정해주는 것.
    - `:<타입>`

- 타입은 소문자로 적어야 하고, 첫 글자를 대문자로 적는 것은 타입 래퍼 객체이며 타입 변환을 할 때 사용.

* 콜론(:) 뒤에 따라오는 것은 타입
- 개발을 하다 보면 any를 써야 하는 상황이 올 수 있지만 noImplicitAny는 true로 해두고 최대한 any는 기피하는 것이 좋음.

### 4.2 함수 타입

#### 4.2.1 함수와 타입 주석

- `function add(a: 인자 타입, b: 인자 타입) 반환 타입 {
    return a + b;
    }`

- 함수에 타입을 달아준다면 반환값에도 타입 추론이 되고 매개변수 타입에도 추론이 되어, 의도한 타입과 다른 타입을 넣으면 경고가 떠서 사전에 에러가 날 수 있는 부분들을 알 수 있음.
- 함수에 타입을 달아줄 때처럼 화살표 함수에도 그대로 달면 됨.
- 함수의 특성상 반환 없이 특정 로직만 수행할 때도 있는데, 그럴 때는 특수한 타입인 void 타입을 쓸 수 있음.

#### 4.2.2 변수와 함수
- ex) const add: Function = addFunction; / 예제처럼 Function 타입을 달면, 이 변수가 함수임을 알 수 있찌만, 어떤 매개변수를 받고 어떤 타입을 반환하는지는 모르기 때문에 잘 사용하지 않음.

- ex) const add: (a: number, b: number) => number = addFunction; / add, minus에 주석으로 단 (a: number, b: number) => number는 함수가 아니라 함수 타입.

#### 4.2.3 함수와 타입 별칭

- 함수형 타입의 예시: `(인수1: 타입, 인수2: 타입) => 반환 타입`

- 함수형 타입의 2가지 문제점
    1. 타입을 재사용하지 못한다는 단점.
    2. 가독성이 정말 좋지 않다.

* 타입 별칭(type aliases)을 사용하면 두 닥지 문제점을 동시에 해결할 수 있음.
    - `type <타입명> = 타입`

### 4.3 enum 타입

#### 4.3.1 리터럴, 숫자, 불리언 타입

* 문자열, 숫자, 불리언 역시도 타입으로 쓸 수 있으며, 여기서 문자열로 된 타입을 **리터럴 타입(literal type)**이라고 함.
* 특히 리터럴 타입에는 템플릿 리터럴(백틱 문자열)이 들어갈 수 있어 타입을 자신이 원하는 형식으로 만들 수 있음.

#### 4.3.2 유니언과 인터섹션 타입

* | 기호(소문자 L, 대문자 i가 아님, shift + \): 프로그래밍에서 흔히 **OR**로 사용되며 여기서도 마찬가지.
    - 합집합이라는 뜻인 **유니언(union)**

* & 기호: 프로그래밍에서 **AND**의 의미.
    - 타입스크립트에서는 이를 **인터섹션(intersection)**이라고 부르며 교집합이라는 뜻.
    * **의미의 관점에서 보면 교집합이지만, 타입의 관점으로 봤을 때는 두 타입을 동시에 만족해야 하므로 마치 합집합**처럼 됨.

#### 4.3.3 enum

* 이넘(enum): 열거형(enumerated)의 준말로 사전에 정해진 값들을 사용하고 싶을 때 사용.

- 이해 안됨
    ```TypeScript
    var EGender;
    (function (EGender) {
        EGender[EGender["male"] = 0] = "male";
        EGender[EGender["female"] = 1] = "female";
        EGender[EGender["etc"] = 2] = "etc";
    })(EGender || (EGender = {}));
    ```
    * 이해하는 중
        - 위 TypeScript 코드는 JavaScirpt에서 대략 이런 객체를 만들고 싶다는 뜻.
        - ```JavaScript
            {
                male: 0,
                female: 1,
                etc: 2,
                0: "male",
                1: "female",
                2: "etc"
            }
        ```
    * ChatGPT 도움으로 이해함.
        * TypeScipt의 enum은 JavaScipt 런타임에서는 특별한 문법이 아니라, **객체를 만들고, 즉시 실행 함수로 그 객체에 값을 채워 넣는 방식**으로 구현됨.
        - TypeScipt 컴파일러는 기존 enum과 합쳐질 가능성, 스코프 관리, 안전한 초기화를 위해 IIFE 형태로 만들어주는 것.
        
        - EGender[EGenter["male"] = 0] = "male";
        - 이것은 사실상 이것.
            EGender["male"] = 0;
            EGender[0] = "male";


- 객체에서 키로 접근하듯이 값을 꺼내 쓸 수 있음.
- 이넘()은 자바스크립트에는 없는 문법이기 때문에 컴파일 결과를 보면, **함수와 객체로 구현**한 것을 확인 가능.

* **이넘()은 열거만 했을 때 0부터 순차적으로 기본값이 설정됨.** 실제로 각 요소마다 값을 넣어주고 싶다면 일일이 입력해야 함.
