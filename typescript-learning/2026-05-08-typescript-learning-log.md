#### 3.1.4 참조 타입 변수

* **참조 타입 변수**(reference type variable): 힙에 저장된 데이터를 참조하며, 참조 주소는 콜 스택에 저장.

* 참조 타입 1. 객체
    * 객체(object): 키(key)와 값(value)으로 구성된 자료구조. 키에는 문자열이나 심벌, 값에는 모든 데이터가 올 수 있음.
        - 객체의 키: 프로퍼티(property)라고도 함
        - 객체에 없는 프로퍼티에 접근할 경우 undefined가 반환됨
        - CRUD: crate, read, update, delete

    - BigO 표기법: O(1), O(n), O(n^2) 등과 같은 표기. 알고리즘의 시간이 얼마나 걸리는지를 비교하기 위한 표기법. O(1)는 실행 시간이 제일 빨라 가장 이상적인 연산.
        - O(1): 입력 크기와 관계없이 일정한 시간
        - O(n): 입력 크기가 커질수록 시간도 비례해서 증가
        - 객체 프로퍼티 접근: 평균적으로 O(1)
        - 배열 순회 탐색: 보통 O(n)

    - 원시 타입 변수는 데이터와 함께 콜 스택에 직접 저장됨.
    - 반면, 참조 타입 변수는 힙에 데이터가 저장되고, 힙에 저장된 데이터의 참조 주소가 콜 스택에 저장됨.

    - 참조: 콜 스택에 주소를 갖고 저장되어 그 주소에 있는 데이터를 바라보는 것

    * 메모리 누수(memory leak)
    * 가비지 컬렉터(garbage collector, GC)

* 참조 타입 2. 배열
    * 배열(array): 데이터가 나열된 자료구조. 각각의 데이터를 요소(element)라고 하며, 각 요소의 위치를 가리키는 숫자를 인덱스(index)라고 함.

    * 인덱스를 셀 때는 맨 앞 0부터 시작해 1씩 더해가며 읽고, 대괄호 안에 인덱스를 적어 원하는 요소에 접근할 수 있음.
    * 음수로 인덱스를 셀 때는 맨 뒤 -1에서 시작해 1씩 빼서 읽고, at(index)로 요소에 해당하는 값을 가져옴.

    - 배열은 내장된 메서드(method)를 활용하여 CRUD 연산을 함. 특히, 배열에는 활용할 수 있는 메서드가 많아 그 활용도가 높음.

* 참조 타입 3. 함수
    * 함수(function): function 키워드로 선언을 하고, 함수 이름과 함께 인수를 넣어주면 실행이 됨.
    * 주의할 점: 함수를 실행할 때 넣는 인수(argument)들과 선언된 매개변수(parameter)들은 1:1 대응이 되어야 함.

    - return은 값을 반환하고 함수를 즉시 종료하는 역할을 함.

    - 타입스크립트에서는 특히 함수의 활용 가능성이 높음. 함수를 변수에 담아 변수처럼 사용할 수도 있음.
    - 익명 함수: 이름이 없음.

    * '함수도 변수처럼 쓸 수 있다.' 함수를 변수에 저장하고, 반환할 수도 있고, 심지어 재귀적으로도 쓸 수 있음. 이는 함수형 프로그래밍의 근간이 되는 중요한 타입스크립트의 특징.

    * 프로그래밍 패러다임: 코드를 작성하는 방법론, 관점, 원칙들을 일컬음.
        * 프로그래밍 패러다임 - 명령형 프로그래밍 vs 선언형 프로그래밍
        - 명령형 프로그래밍 -> 객체지향 프로그래밍 vs 절차지향 프로그래밍
        - 선언형 프로그래밍 -> 함수형 프로그래밍
        * 명령형은 How에 집중하고, 선언형은 What에 집중하여 프로그래밍하는 것을 말함.
        * **타입스크립트는 포로토타입 기반의 객체지향형 언어이면서도 함수형 프로그래밍을 지원함**
        - 프로그래밍 패러다임은 전공자들도 최소 6개월간 수업을 들으며 배우는 과정. 좋은 개발자가 되려면 필수로 공부해야 하는 개념.

#### 3.1.5 얕은 복사, 깊은 복사

* 원시 타입 변수들은 복사를 하고 값을 마음대로 바꾸어도 상관없음.
* 하지만 참조 타입 변수들은 복사를 할 때 **내가 무슨 복사를 하고 있는지 정확하게 이해하는 것이 중요함**

* **얕은 복사**(shallow copy): 데이터 자체를 복사하는 것이 아니라 힙에 있는 주소를 복사하여 같은 값을 참조하는 복사

* const는 한 번 값을 할당하면 값을 바꿀 수 없다. 얕은 복사에서 힙에 있는 값은 바뀌지만, **콜 스택에 있는 주소값은 바뀌지 않는다.**

- 얕은 복사는 주소를 복사해 같은 데이터를 참조했다면, 깊은 복사는 데이터 자체를 복사해서 새로운 데이터를 참조함. 따라서 원본을 훼손할 가능성도 없고, 변화도 감지할 수 있음.

* 깊은 복사 방법 1. 스프레드 연산자(전개 연산자)
    * 방법은 간단하지만, **객체 안에 객체들까지 깊은 복사를 하지 못한다(중첩된 객체는 참조를 유지한다)는 단점**이 있음.
    - 객체의 깊이(depth)가 1보다 깊을 때는 이를 인지하고 사용해야 함.

* 깊은 복사 방법 2. lodash 패키지

#### 3.1.6 조건문과 반복문

* 연산자
    1. 비교 연산자
        * ==는 같은 값인지를 보고, ===는 같은 값이고 자료형까지 같은가를 비교함.
            - == 값이 동일하다.
            - != 값이 다르다.
            - === 자료형과 값이 동일하다.
            - !== 자료형이나 값이 다르다.
        * 프로그래밍에서는 숫자뿐만 아니라 문자도 부등호로 비교할 수 있음. 문자를 숫자처럼 대소 비교할 수 있는 이유는 문자를 아스키 코드로 변환해서 코드의 숫자를 비교하기 때문.

        - 아스키(ASCII): American Standard Code for Information Interchange의 줄임말. 종보 교환을 위한 부호 체계.
        - 유니코드(Unicode), UTF-8
    2. 논리 연산자
        * 논리 연산자는 결괏값을 항상 불리언값으로 도출하는 연산자. 불리언은 참과 거짓을 나타내는 데 쓰이며, 참은 1 또는 true, 거짓은 0 또는 false로 나타냄.
    3. 자주 사용하는 연산자
        * typeof 연산자: 변수나 값의 타입을 반환해주는 연산자. typeof 연산자는 결과를 항상 문자열로 반환해주기 때문에 typeof를 두 번 연속으로 쓰면 결과는 항상 문자열이 나옴.
        * instanceof: 해당 클래스의 인스턴스가 맞는지 확인할 수 있는 연산자.
        * in 연산자: 객체에 접근해서 작업할 일이 있다면 in 연산자로 해당 키가 있는지 확인하고, true일 경우에만 작업을 수행하면 됨.

* 조건문
    * if - else if - else: if 문은 특정 조건이 true일 때 로직을 실행하는 식으로, 조건식이라고 함. if 문은 위에서부터 내려오면서 만족하는 조건의 if 문을 단 한 번만 실행함.
        - if와 else는 한 번씩만 등장할 수 있지만, else if는 여러 번 등장할 수 있음.
        - 조건문에서는 아래의 조건들을 만족한다고 하더라도 조건을 만족하는 순간 해당 로직을 실행하고 다시 조건문을 탐색하지 않음. 즉, **위에서부터 만족하는 조건문 한 부분만 실행함.**
        - if 문은 내용이 한 줄일 때 중괄호를 생략할 수 있음.
        - true일 때 if 문을 적용하는 것이 아니라, false일 때 탈출하는 식의 로직을 짜면 코드가 깨끗해짐. 이는 클린 코드(clean code)에서도 권장하는 사항.

        * 클린 코디(clean code): 읽기 쉬운 코드, 단순하고 직관적인 코드를 듯함.

        * if 문은 기본적으로 값이 있다면 참으로 인식하지만, false로 인식하는 값들도 있음. 0, null, undefined, NaN, 빈 문자열("")
        - NaN: Not-A-Number, 숫자를 계산할 때 엉뚱한 값이 껴들어가면 나오는 값.
        * **빈 문자열("")에 띄어쓰기가 하나라도 들어가면 true로 인식.**
        * **빈 배열([])과 빈 객체({})는 true로 인식.** 다른 방법으로 빈 배열인지, 빈 객체인지 확인해야 함.
    
    * switch
        * switch 문은 여러 조건을 검사하여 그중 하나에 해당하는 코드를 실행함.
        - if, else if, else로도 구현할 수 있지만, switch 문을 사용하면 더 직관적이고 가독성 있게 코드를 작성할 수 있음.

        * 타입스크립트를 실행하는 인터프리터는 위에서부터 아래로 읽어가는 특징이 있음. switch 문에는 break가 없다면 case 밑으로 모든 코드들이 실행되니 주의.

    * 배열과 반복문
        * for: 반복 작업을 수행할 때 사용하는 기본적인 반복문. 특정 조건이 참인 동안 코드를 반복 실행하는 데 사용되며, 주로 반복 횟수가 정해져 있을 때 사용함.
            - ```typescript
                for (시작값; 조건식; 증가식) { 실행 로직 }
                ```
            
            * 'How', 즉 '어떻게'에 초점이 맞춰진 방식을 **명령형(imperative) 프로그래밍**이라고 함.
            * 반면, **선언형(declarative) 프로그래밍**은 'What', 즉 '무엇을'에 초점을 맞춘 패러다임.

            - forEach vs map
                * forEach는 배열을 순회하며 특정 로직을 수행.
                * map은 기존 배열을 새로운 배열로 반환하는 데 사용.

        * while: 조건식이 true일 때만 반복해서 코드 블록을 실행하는 반복문. 반복 횟수가 정해지지 않은 경우나 특정 조건이 충족될 때까지 반복 작업을 수행할 때 유용함.
            * while 문에서 조심해야 할 점은 조건을 true 또는 1처럼 true값을 넣어버리면 무한 루프를 돈다는 것. 무한 루프가 생기면 애플리케이션이 멈추게 되므로 조심해야 함. while 문에서 항상 참인 조건식을 넣었을 때는 무한 루프를 돌지 않게 꼭 break로 탈출하는 조건을 걸어주어야 함.

### 3.2 ESNext 문법

#### 3.2.1 템플릿 리터럴

* **템플릿 리터럴**(template literal): 자바스크립트에서 문자열을 더 편리하고 가독성 있게 작성할 수 있도록 도와주는 문자열 리터럴.
    * 백틱(`): 문자열 안에서 ${변수 혹은 표현식}을 활용하면 삼항 연산자, 수식, 여러 줄 문자열 등을 작성할 수 있음.

    - 이스케이프 문자(escape character): 문자열 데이터를 사용할 때 특수한 기능을 수행하는 문자(작은따옴표, 큰따옴표, 줄 바꿈, 탭, 역 슬래시 등). 이스케이프 문자는 특수문자임을 알리는 역슬래쉬(\)와 함께 사용.
        - \`: 작은따옴표
        - \": 큰따옴표
        - \n: 줄 바꿈
        - \t: 탭
        - \\: 역슬래쉬
    
    - 삼항 연산자: 조건에 따라 값을 간단하게 선택할 수 있는 연산자.
        - 구조: `조건식 ? 조건식이 참일 때의 값 : 조건식이 거짓일 때의 값`

#### 3.2.2 객체 리터럴

* ESNext에서는 기존 접근 제한자(.)뿐만 아니라 대괄호([])를 활용하여 접근할 수 있음. 대괄호 안에는 다양한 표현식들이 들어갈 수 있어 더 유연하게 객체를 조작할 수 있음.

* ESNext에서는 key와 value의 이름이 같다면 생략할 수 있는 기능이 추가됨.
- 객체 내부 함수(메서드)도 생략할 수 있음. 기존에는 function 키워드를 입력해서 메서드를 만들었지만, 키워드를 생략하고 프로퍼티 이름에 소괄호를 같이 적어주면 좀 더 직관적이고 짧은 코드로 메서드를 선언할 수 있음.

#### 3.2.3 화살표 함수

* **화살표 함수**(arrow function): 기존 function 키워드 대신에 화살표(=>)로 함수를 선언함.
    - 화살표 함수는 함수 이름 없이 바로 사용이 가능하기 때문에 **익명 함수**로 쓰일 수도 있고, **람다 함수**로도 불림.
    - 객체를 한 줄로 반환할 때는 바로 중괄호를 적으면 이것이 함수의 중괄호인지 객체의 중괄호인지 타입스크립트가 알 수가 없음. 따라서 **소괄호로 한 번 감싸서 객체를 반환**해야 함.
    - **매개변수가 1개일 때는 소괄호를 생략**할 수도 있음.

    * function으로 만들어진 함수와 매우 중요한 차이점
        - function 키워드로 만든 함수에서 this **객체는 함수를 호출한 주체**가 됨.
        - 일반 함수에서 화살표 함수로 바꾸기만 했는데, 출력되는 결과가 달라짐. 화살표 함수는 상위 콘텍스트의 this를 따름.
        - 함수를 선언하고, 호출하는 것에 따라 this 객체가 달라지는 특징.

        * function 함수와 화살표 함수에는 **호이스팅(hoisting)**이라는 매우 중요한 차이점이 있음.
        - 호이스팅: 인터프리터가 변수나 함수를 미리 할당하는 것
        * **function으로 선언한 함수는 호이스팅이 일어나고, 화살표 함수는 호이스팅이 일어나지 않음.**
