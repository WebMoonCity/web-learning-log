### 4.4 인터페이스
- 인터페이스는 타입스크립트 문법 중에서 가장 자주 쓰이는 문법이라고 해도 과언이 아님.

#### 4.4.1 인터페이스 기본
* 인터페이스(interface)
    - 객체에 타입을 입력할 때와 객체를 설계할 때 사용됨.
    - 타입스크립트의 거의 모든 것이 객체인 만큼 활용할 수 있는 여지가 많음.
    - 실전 프로젝트에서 개발을 할 때도 객체, 함수, 인터페이스가 높은 비중을 차지함.

    * 인터페이스는 객체 속성들과 속성의 타입들을 정함.

    - 인터페이스는 type 키워드로 만들 수 있는데 선언할 때 사용된 인터페이스를 익명 인터페이스라고 함.
    - interface와 type으로 선언한 인터페이스는 기능은 같지만, 기능상 조금의 차이가 있음.
    * interface 키워드로 만든 인터페이스는 주로 설계, 클래스와 함께 쓰임.
    * type 키워드로 만든 인터페이스는 보통 변수의 타입을 정할 때 사용함.

    - 인터페이스를 타입으로 준 변수는 정의한 속성들과 타입을 맞춰주면 됨.

    * 인터페이스에 있는 프로퍼티들은 객체에 반드시 존재해야 함. 만약 로직에 다라 없을 수도 있는 프로퍼티가 존재할 경우에는 **끝에 물음표(?)를 붙여 옵셔널 프로퍼티(optional property)로 선언**하면 됨.
    * const로 객체를 선언하면 새로운 객체의 할당이 안 될 뿐, 안에 있는 프로퍼티는 바뀔 수 있음. 프로퍼티가 바뀌는 것을 원하지 않을 때는 **readonly를 앞에 추가하여 프로퍼티를 선언**하면 됨.

#### 4.4.2 인터페이스 응용

```TypeScript
interface IUser {
    name: string;
    [props: string]: string;
}

const k: IUser = {
    name: "kkh",
    job: "police",
};

const g: IUser = {
    name: "leeG",
    team: "sanb",
}
```

* 객체의 프로퍼티가 동적인 경우에도 **인덱서블 타입(indexable type)**을 활용하여 타입을 만들 수 있음.

```TypeScript
enum EColor {
    red,
    blue,
    green,
}

type IColor = {
    [keys in EColor]: string;
};

type IIColor = {
    [props in "red" | "blue" | "green"]: string;
};
```

* keys(props)를 in으로 해서 프로퍼티로 받아야 하는 범위를 줄임. 다만, **in은 interface 키워드로 만든 인터페이스에서는 사용할 수 없으므로, type 키워드와 익명 인터페이스를 활용.**

* keyof를 활용하면 인터페이스의 key들만 추출하여 사용할 수 있음.

* 인터페이스(interface)는 extends 키워드로 다른 인터페이스를 상속받을 수 있다는 특징이 있음.

* 인터페이스 상속은 클래스 상속과 개념 자체는 비슷함. 하지만 **다중 상속이 가능하다는 가장 큰 차이가 있음.** 인터페이스는 한 번에 여러 부모를 가질 수 있음.

#### 4.4.3 인터페이스와 함수

- 타입스크립트의 모든 것은 객체.
- 대체적으로 인터페이스, 함수, 객체를 가장 많이 사용함.

- 잘 사용하지는 않지만 객체(인스턴스)를 만들 때 쓰는 new 키워드로도 함수를 만들 수 있음.
- 함수도 객체. 생각을 확장하여, 객체 명세를 작성하는 인터페이스와 함수를 같이 사용할 수 있음.

* ChatGPT로 추가 공부
    - interface는 주로 객체의 구조를 정의할 때 씀.
    - type은 객체뿐 아니라 더 다양한 타입 조합을 만들 때 씀.

    - interface는 같은 이름으로 다시 선언하면 합쳐짐.
    - 반면 type은 같은 이름으로 두 번 만들 수 없음.

    - 둘다 확장 가능.
    - interface는 extends로 확장.
    - type은 &를 써서 확장.

    - 실무적으로,
    - 객체의 모양을 정의 -> interface
    - 유니온, 리터럴, 함수 타입, 복잡한 조합을 만듬 -> type

    - 이런 느낌.
    - interface: "이 객체는 이런 구조를 가져야 한다."
    - type: "이 타입 표현식에 이름을 붙이겠다."
