## 5 타입스크립트 예제

### 5.1 클래스와 인터페이스

* 항상 기능을 구현할 때는 자신이 **만들고 있는 기능이 어떤 파라미터를 받고 어떤 결과를 반환하는지 명세를 작성하고 그다음에 개발에 착수**해야 함.

* 개발자는 필요한 기능의 명세를 인터페이스에 작성하고, 구현체는 자유롭게 갈아끼울 수 있음.

- JPA(Java Persistence API): Java에서 ORM을 사용하기 위한 표준 인터페이스/명세.
- ORM(Object-Relational Mapping): 객체-관계 매핑. 객체와 데이터베이스 테이블을 자동으로 연결해주는 기술.

- JPA와 ORM의 관계
- ORM = 객체와 DB 테이블을 연결하는 기술/개념
- JPA = 자바에서 ORM을 쓰기 위한 표준 명세

### 5.2 추상 클래스와 인터페이스

* 추상 클래스에서의 다형성: 추상 클래스 타입 하나로 여러 자식 객체를 다루면서, 실제 동작은 각 자식 클래스의 구현에 맡기는 객체지향 원리 by ChatGPT.

* 추상클래스는 다형성 등의 목적으로 존재하는 클래스이며, 인스턴스를 만들 수 없는 클래스. 인스턴스를 만들 수 없기 때문에 추상 클래스를 상속받는 자식 클래스가 그 기능을 구현해야 함.
- 클래스 키워드 앞에 abstract 키워드를 붙이면 추상 클래스가 됨.

* **언제 인터페이스와 추상 클래스를 쓰나요?**
    - 인터페이스는 클래스가 필요한 기능의 명세를 작성하는 것이 목적.
    - 추상클래스는 **공통된 기능을 가지는 클래스들을 위한 기초 구조**로 사용되고, **상속을 통해 구현을 공유**할 때 적합함.
    - 인터페이스는 **다양한 클래스가 특정 기능을 구현하도록** 할 때 사용됨.

* 다형성(polymorphism)
- UML(Unified Modeling Language): 통합 모델링 언어. 모델링을 할 때 사용되는 언어. 다양한 목적과 관점에 맞게 다이어그램을 도식화하는 데 주로 사용됨. 규모가 큰 프로젝트일수록 사전 설계를 꼼꼼히 하고, 설계를 할 때 UML을 가장 많이 채택함.

- 실제 프로젝트 시, 개발을 시작하기 전에 UML로 디자인과 문서화를 하고 만드는 것이 좋음. 또한 설계라는 것은 항상 상황과 요구사항에 맞게 유동적으로 변해야 함. 절대적인 것은 없음.
