### 4.5 클래스와 데커레이터

- 타입스크립트에서 클래스는 객체 지향 설계를 구현하기 위한 강력한 문법.
- 데커레이터는 이러한 클래스의 동작을 동적으로 확장하고 수정할 수 있는 강력한 문법.

#### 4.5.1 클래스

* 접근 제한자(access modifier): 필드에 대한 접근을 제한하는 데 어디까지 제한을 할 것인지 정하는 것.

- UML(Unified Modeling Language): 통합 모델링 언어. 모델링을 할 때 사용되는 언어. 다양한 목적과 관점에 맞게 다이어그램을 도식화하는 데 주로 사용됨. 규모가 큰 프로젝트일수록 사전 설계를 꼼꼼히 하고, 설계를 할 때 UML을 가장 많이 채택함.

- 타입스크립트에서는 접근 제한자에 특별한 기능이 있음. 즉, **생성자 함수의 파라미터 앞에 접근 제한자를 달아주면 필드를 초기화하는 코드를 생략**할 수 있음.
- 접근 제한자
|:---:|:---:|:---:|:---:|
|:---:| public | protected | private |
| 외부에서 접근 | ○ | × | × |
| 자식이 접근 | ○ | ○ | × |
| 내부에서 접근 | ○ | ○ | ○ |
| UML상에서 표기 | + | # | - |

- ○ ×

- 파라미터(parameter): 함수가 값을 받을 때 쓰는 입구 변수.
- 인자(argument): 실제로 넣어주는 값.

- 일반적인 방식
```TypeScript
class User {
    private id: number;
    publick name: string;
    
    constructor(id: number, name: string) {
        this.id = id;
        this.name = name;
    }
}
```

- TypeScript의 축약 방식
```TypeScript
class User {
    constructor(
        private id: number,
        public name: string,
    ) {}
}
```

* 상황에 따라 천차만별이지만 실전 프로젝트에서 개발을 하면 필드값은 외부의 접근을 막기 위해 대부분 private으로 선언함. 필드값을 private로 선언하면 값을 설정하고 가져올 때 **세터(setter)**와 **게터(getter)**를 이용해야 함.

* compilerOptions에서 target 옵션을 ES6 이상으로 했을 때는 **private 접근 제한자를 생략하고 대신 필드에 #을 붙여줘도 동일한 의미**가 됨.

* 게터니는 'get <필드이름>'으로 세터는 'set <필드이름>'으로 선언하며 필드의 값을 가져올 때는 자동으로 게터가 호출되고, 값을 변경하면 자동으로 세터가 호출되어 값이 변경됨.
* '왜 귀찮게 private, getter, setter를 쓰지?'
    - 외부에서 임의로 값을 변경하는 것을 방지할 수 있음.
    - 데이터의 무결성을 지킬 수 있음.

- 필드: 객체 내부에 붙어 있는 값
- 필드 vs 메서드
    - 필드: 객체가 가진 데이터
    - 메서드: 객체가 할 수 있는 동작
    - 필드는 "상태/정보", 메서드는 "동작/기능"

* 타입스크립트에서 인터페이스는 다양한 용도로 사용할 수 있음. 특히 인터페이스와 클래스는 서로 떼려야 뗄 수 없는 관계.

- implements의 장점: 다중 상속이 가능해진다는 것.
- 타입스크립트에서 클래스는 단일 상속만 가능하지만, 인터페이스가 다중 상속이 가능하다는 것을 이용하면 설계상으로 다중 상속을 할 수 있음.
- **implements한 인터페이스는 반드시 구현**해야 하므로 재사용성이 높아지지는 않음.
