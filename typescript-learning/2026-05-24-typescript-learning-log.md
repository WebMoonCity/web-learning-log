### 5.8 interface vs. type

- 인터페이스에는 interface 키워드로 만드는 인터페이스가 있고, type 키워드로 만드는 인터페이스가 있으며, 이 둘에는 차이가 있음.

- 타입의 확장에서 차이가 있음.
    - interface로 만든 인터페이스는 extends를 사용해서 타입을 확장함.
    - type으로 만든 인터페이스는 인터섹션 타입을 사용함.

* **type 키워드로 만든 인터페이스는 유니온 타입과 인터섹션 타입의 사용이 자유롭다** 보니, 더 유연한 타입을 가질 수 있음. 그뿐만 아니라 유틸리티 타입과 함께 사용할 때도 저장을 할 수 있기 때문에 클래스와 함께 사용할 경우를 제외하고는 보통 type 키워드를 사용함.

- 유틸리티 타입: 기존 타입을 재료로 삼아 새 타입을 만드는 TypeScript 내장 도구.
    - 예: `Omit<User, "id">;` `Partial<>;` `Pick<User, "id" | "name">;`

#### 4.5.2 데커레이터

* 데커레이터(decorator): 런타임에 실행되어 클래스, 메서드, 프로퍼티 등에 동적으로 메타데이터나 기능을 조작하는 기능.
    - 데커레이터는 처음 접한다면 난해한 개념. 이해가 어렵다면 **'데커레이터는 함수다!'**라는 것만 알아도 충분함.

* **데커레이터는 클래스 위에서 작동하는 문법이며 단독으로 사용하지 않음.**
- 데커레이터는 클래스와 필드 위에 `@함수명` 꼴로 달아주면 됨.
- 데커레이터 함수의 첫 파라미터 originalMethod에는 함수 원본이 넘어오고, 두 번째 인수 _context에는 관련된 메타 정보들이 넘어오게 됨.

* **데커레이터가 클래스가 선언될 때(init될 때) 런타임에서 실행됨.**

* 기본적으로 데커레이터는 콘셉트 자체가 인수에 메타 정보가 넘어오는 콘셉트.

#### 4.5.1 클래스
- 게터와 세터가 기억 안나 다시 배우기 위해.

- 필드값을 private로 선언하면 값을 설정하고 가져올 때 **세터(setter)와 게터(getter)**를 이용해야 함.

- implements의 장점으로는 다중 상속이 가능해짐. 타입스크립트에서 클래스는 단일 상속만 가능하지만, 인터페이스가 다중 상속이 가능하다는 것을 이용하면 설계상으로 다중 상속을 할 수 있음. **implements한 인터페이스는 반드시 구현**해야 하므로 재사용성이 높아지지는 않음.
